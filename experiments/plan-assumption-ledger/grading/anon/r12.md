# RSI-Reflect + Self-Compact Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship two complementary packages: (1) **self-compact** — an unattended-only supervisor that hard-resets a `claude -p` process's context via `tasks/mission.md` when it crosses ~70% fill (≈30% remaining of a 1M window), instead of waiting for lossy native `/compact`; (2) **rsi-reflect** — wires `session-reflect`'s existing per-session reflection artifacts (and self-compact's own reset events) into the `recursive-self-improvement` daily-review prompt as a cheap, pre-digested analysis source.

**Architecture:** Self-compact adds a `Stop` hook (`skills/self-compact/hooks/stop-check.sh`) that only acts when a new env sentinel `SELF_COMPACT_SUPERVISED=1` is present — set exclusively by a new outer-loop script (`skills/self-compact/run-autonomous.sh`) that repeatedly launches `claude -p` headlessly. When context fill crosses threshold, the hook synchronously refreshes `tasks/mission.md` (reusing `session-reflect`'s already-built `mission` mode — the same call idle-handoff.sh already makes) and drops a marker file; `-p` mode then exits naturally (no forced mid-turn `/compact`/`/clear` needed — that capability is unverified, so this plan avoids depending on it). The supervisor sees the marker, archives it as an `rsi-reflect` artifact, and relaunches `claude -p` **without** `--resume` — a genuine reset, not a summary. Fill-percentage detection is extracted into one shared module so `self-compact` and the existing interactive advisory hook (`context-baggage.py`) can never drift apart on the threshold. rsi-reflect then teaches the RSI daily-review prompt to read `session-reflect`'s `final.json`/checkpoints and self-compact's new event log as a first-pass source, falling back to raw transcripts only when needed.

**Tech Stack:** bash (hooks, supervisor), Python 3.10+ (shared detector, reused stdlib-only), jq, Claude Code hooks (`Stop`, `SessionStart` matcher `compact|clear`), existing `session-reflect` skill's `mission` mode, existing `orchestrate` skill's `compact-reinject.sh`.

#!/usr/bin/env python3
"""Shared context-window fill-percentage detector.

Used by context-baggage.py (interactive advisory nudge, repo root) and
skills/self-compact/hooks/stop-check.sh (autonomous auto-reset trigger) so
both share one threshold-detection implementation and can't drift apart.

Context window detection (in priority order):
    1. CLAUDE_CONTEXT_MAX env var (explicit override, in tokens)
    2. Model ID prefix — Opus/Sonnet 4.x+ run with 1M in this setup
    3. Observed usage — if any assistant turn exceeded 200k tokens, the
       session is 1M regardless of model name
    4. Default 200k
"""
from __future__ import annotations

import json
import os

BASE_MAX = 200_000
ONE_M = 1_000_000
DEFAULT_THRESHOLD = 0.70

ONE_M_MODEL_PREFIXES = (
    "claude-opus-4-",
    "claude-sonnet-4-",
    "claude-opus-5",
    "claude-sonnet-5",
)
ONE_M_MARKER = "[1m]"


def detect_max_tokens(model: str | None, observed_max: int) -> int:
    override = os.environ.get("CLAUDE_CONTEXT_MAX")
    if override:
        try:
            return int(override)
        except ValueError:
            pass
    if model:
        if ONE_M_MARKER in model.lower():
            return ONE_M
        if any(model.startswith(p) for p in ONE_M_MODEL_PREFIXES):
            return ONE_M
    if observed_max > BASE_MAX:
        return ONE_M
    return BASE_MAX


def compute_fill(transcript_path: str) -> dict:
    """Scan a transcript JSONL and return fill-percentage state.

    Returns {"fill_pct": float, "max_tokens": int, "model": str|None,
    "last_usage": dict|None, "user_msg_count": int}.
    """
    if not transcript_path or not os.path.exists(transcript_path):
        return {"fill_pct": 0.0, "max_tokens": BASE_MAX, "model": None,
                 "last_usage": None, "user_msg_count": 0}

    user_msg_count = 0
    last_usage = None
    last_model = None
    observed_max = 0

    with open(transcript_path, "r", errors="replace") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            try:
                obj = json.loads(line)
            except json.JSONDecodeError:
                continue
            obj_type = obj.get("type")
            if obj_type == "user":
                user_msg_count += 1
            elif obj_type == "assistant":
                msg = obj.get("message", {})
                model = msg.get("model")
                if model and model != "<synthetic>":
                    last_model = model
                usage = msg.get("usage")
                if usage:
                    last_usage = usage
                    total = (
                        usage.get("input_tokens", 0)
                        + usage.get("cache_creation_input_tokens", 0)
                        + usage.get("cache_read_input_tokens", 0)
                    )
                    if total > observed_max:
                        observed_max = total

    max_tokens = detect_max_tokens(last_model, observed_max)

    if last_usage:
        total_tokens = (
            last_usage.get("input_tokens", 0)
            + last_usage.get("cache_creation_input_tokens", 0)
            + last_usage.get("cache_read_input_tokens", 0)
        )
        fill_pct = total_tokens / max_tokens
    else:
        file_size = os.path.getsize(transcript_path)
        fill_pct = file_size / (max_tokens * 4)

    return {
        "fill_pct": fill_pct,
        "max_tokens": max_tokens,
        "model": last_model,
        "last_usage": last_usage,
        "user_msg_count": user_msg_count,
    }


if __name__ == "__main__":
    import sys
    if len(sys.argv) != 2:
        print(json.dumps({"error": "usage: context_fill.py <transcript_path>"}))
        sys.exit(2)
    print(json.dumps(compute_fill(sys.argv[1])))
```

#!/usr/bin/env python3
"""
UserPromptSubmit hook: warns when context is over THRESHOLD with potentially
stale/off-topic content. Fires every MESSAGE_INTERVAL user messages once
threshold is met.

Fill-percentage detection lives in skills/self-compact/lib/context_fill.py,
shared with the autonomous self-compact Stop hook so the two paths (ask a
human here; auto-act there) can never disagree on what "70% full" means.
"""
import json
import os
import sys

sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)),
                                 "skills", "self-compact", "lib"))
from context_fill import compute_fill, DEFAULT_THRESHOLD  # noqa: E402

# Raised from 0.25 -> 0.70 on 2026-08-08 after measuring 95.5% cache-hit
# ratio across 7 days / $3,073 spend (probes/analyze_sessions.py). At that
# hit ratio, holding baggage is cheap and resetting is expensive
# (cache_write ~$5-10 per cold event). Nudge should fire when handoff to
# a fresh session starts to pay off, not on any drift.
THRESHOLD = DEFAULT_THRESHOLD
MESSAGE_INTERVAL = 5


def main():
    try:
        data = json.load(sys.stdin)
    except Exception:
        sys.exit(0)

    transcript_path = data.get("transcript_path", "")
    if not transcript_path or not os.path.exists(transcript_path):
        sys.exit(0)

    state = compute_fill(transcript_path)
    user_msg_count = state["user_msg_count"]

    if user_msg_count == 0 or user_msg_count % MESSAGE_INTERVAL != 0:
        sys.exit(0)

    fill_pct = state["fill_pct"]
    if fill_pct < THRESHOLD:
        sys.exit(0)

    max_tokens = state["max_tokens"]
    pct_display = int(fill_pct * 100)
    message = (
        f"Context is {pct_display}% full ({user_msg_count} messages in this session; "
        f"window: {max_tokens // 1000}k tokens). "
        "At this fill, a fresh-session handoff via tasks/mission.md is usually cheaper "
        "than an in-place /compact: --fork-session on a warm cache measured ~77% hit "
        "(session-reflect empirical), while /compact invalidates the prefix and forces "
        "cache_write on subsequent turns. "
        "Suggest to the user: (a) write tasks/mission.md (done / next / blocked / open "
        "questions), (b) start a fresh session in the same cwd and load it, OR (c) "
        "continue here and accept the drift. Ask which."
    )
    print(json.dumps({"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": message}}))


if __name__ == "__main__":
    main()
```

PROMPT="${2:?usage: run-autonomous.sh <worktree-dir> \"<initial prompt>\" [--sigil TEXT] [--max-resets N]}"

    --sigil) SIGIL="$2"; shift 2 ;;

    --) shift; EXTRA_ARGS+=( "$@" ); break ;;
    *) echo "run-autonomous.sh: unknown arg $1" >&2; exit 2 ;;
  esac
done

RESET_COUNT=0
CURRENT_PROMPT="$PROMPT"

  fi

# Self-Compact

Autonomous companion to `orchestrate` and `session-reflect`. An armed
`ralph-loop` keeps ONE session's context growing until native auto-compact
(lossy, late, ~95%) or the human intervenes. Self-compact instead HARD
RESETS the process at a configurable fill threshold (default 70% —
`SELF_COMPACT_THRESHOLD`, matches `context-baggage.py`'s advisory nudge),
using `tasks/mission.md` as the entire handoff — the same lossless
disk-based mechanism `session-reflect`'s mission mode and
`scripts/idle-handoff.sh` already use, generalized from "reactive/idle" to
"proactive/threshold-triggered."

## When to use it

Only for unattended runs — a human is not going to be watching the
terminal and choosing between compact/clear/continue turn by turn. For
interactive sessions (including an interactively-armed `ralph-loop` where
a human IS watching), do nothing different — `context-baggage.py`'s
existing UserPromptSubmit nudge already asks the human which of
mission.md-handoff / fresh-session / continue-and-accept-drift they want.
Self-compact's auto-action is gated on `SELF_COMPACT_SUPERVISED=1`, an env
var ONLY `run-autonomous.sh` sets — nothing else in this repo will
accidentally trigger it.

## How it works

1. `run-autonomous.sh <worktree-dir> "<prompt>" [--sigil TEXT] [--max-resets N]`
   launches `claude -p` headlessly with `SELF_COMPACT_SUPERVISED=1` in its
   env.
2. Every `Stop` event, `hooks/stop-check.sh` computes context fill via
   `lib/context_fill.py` (shared with `context-baggage.py` — one threshold
   definition, can't drift). Below threshold: no-op.
3. At/above threshold: synchronously runs `session-reflect/reflect.sh
   mission` to refresh `tasks/mission.md` (same call shape as the
   PreCompact 2nd-compact defence and `idle-handoff.sh`), then drops
   `.claude/self-compact-reset.local` and records an artifact under
   `~/.claude/reflections/self-compact/` for `recursive-self-improvement`
   to read later (see `recursive-self-improvement/config/prompt.md`).
   `-p` mode always exits after one turn regardless, so the process ends
   here naturally — no forced mid-turn compact/clear is attempted.
4. `run-autonomous.sh` sees the process exit, finds the reset marker,
   archives + clears it, and relaunches `claude -p` FRESH (no `--resume`)
   with a continuation prompt pointing at `tasks/mission.md`,
   `tasks/progress.md`, `tasks/session-constraints.md`. Zero carried
   context — this is the actual reset, not a summarization.
5. `orchestrate/hooks/compact-reinject.sh` (SessionStart `compact|clear`)
   also clears the marker if it beats step 4 to it and prints a one-line
   confirmation — idempotent either way, no ordering requirement.
6. The loop continues until a configured `--sigil` matches the model's
   final text, `--max-resets` is exceeded (default 20 — safety valve
   against a mission.md that never gives the resumed session enough
   runway), or a turn ends with no sigil and no reset marker (ambiguous
   natural ending — the supervisor stops rather than guessing).

## Non-goals

- Does not replace `ralph-loop`'s in-session Stop-block continuation for
  interactive use — orthogonal mechanism, different trigger, different
  gating.
- Does not attempt a mid-turn `/compact` or `/clear` self-invocation via
  the model calling a tool — genuinely uncertain whether that's supported
  mid-generation; process-restart is the mechanism actually verified to
  work with this codebase's existing hooks (see Task 1's spike in the
  implementation plan).
- Does not decide permission mode / `--dangerously-skip-permissions` for
  you — pass through whatever flags the run needs via `--`, same as any
  other headless invocation (see `locked-down-headless-agent`).
